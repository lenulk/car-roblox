# งานสำหรับ Kiro: ทำให้ NPC ดูเป็นธรรมชาติขึ้น (5 ข้อ)

## บริบท
- โปรเจกต์ Roblox (Rojo + Luau `--!strict`) ตัวละคร NPC สร้างใน `src/server/Npc/NpcBuilder.luau` ด้วยสีกับชิ้นส่วนเล็ก ๆ ที่ weld เอง **ไม่ใช้ asset ID ใด ๆ** ท่าทางทั้งหมดเป็น procedural ผ่าน `Motor6D.Transform` (layer: walk / idle / work + `setCarry`)
- ผู้ใช้งาน NPC: `src/server/Services/EmployeeService.luau` (พนักงาน), `src/server/Services/ShopperService.luau` (ลูกค้าเดินซื้อของ), `src/server/Services/HireService.luau`
- อ่าน `docs/CONTRACT.md` และ `docs/TODO.md` ก่อนเริ่ม
- **สิ่งที่มีอยู่แล้ว อย่าทำซ้ำ:** เฟสเวลาของแต่ละ layer สุ่มตั้งแต่สร้าง (`newLayer`), idle มีหายใจ/ถ่ายน้ำหนัก/หันหัวช้า ๆ อยู่แล้ว (`poseIdle`), `walkPath` มีเร่ง-ชะลอ และหมุนตัวนุ่มอยู่แล้ว, `idle.wave` มีแล้ว งานนี้คือ "ต่อยอด" ไม่ใช่เขียนใหม่

## กติกาที่ต้องทำตาม
1. ห้ามใช้ asset ID (เสียง/รูป/mesh/animation) ถ้าอยากได้เสียงให้ข้าม แล้วจดไว้ใน TODO ว่ารอไฟล์ที่ตรวจ ID ได้
2. **ใช้เฉพาะ Enum ที่มีจริงใน Roblox** — ครั้งก่อนเคยใช้ `Enum.Material.Rust` ซึ่งไม่มี ทำให้ `StationModels.build` ล้มเงียบ ๆ ก่อนใช้ Enum/property ใดที่ไม่แน่ใจ ให้ตรวจเอกสาร Roblox ก่อน
3. สไตล์โค้ดให้เหมือนไฟล์เดิม (tab, ปริมาณคอมเมนต์, ตั้งชื่อ) `--!strict` ต้องไม่มี type error
4. ใช้ Heartbeat ตัวเดียวที่มีอยู่แล้ว (`step`/`activeRigs`) ห้ามเพิ่ม loop ต่อ NPC หรือ `while true do wait()` ต่อ NPC เพิ่ม
5. ทุกอย่างที่สร้างใหม่ (particle, connection, attach part) ต้องถูกเก็บกวาดเมื่อ NPC ถูก Destroy (`model.Destroying` / ลูกของ model)
6. ห้ามเพิ่ม RemoteEvent ใหม่ งานนี้เป็นฝั่ง server ล้วน
7. ห้ามแตะ `GarageTycoon.rbxlx`, ห้าม `git commit`, ห้ามแก้ไฟล์ที่ไม่เกี่ยว
8. อย่าทำให้ API เดิมพัง: `walkCycle / idle / work / setCarry / place / turnTo / walkPath` ต้องเรียกแบบเดิมได้ ถ้าเพิ่มฟังก์ชันใหม่ให้เพิ่มเฉพาะที่จำเป็น

## ข้อ 1 — สุ่มบุคลิกต่อ NPC
เป้าหมาย: NPC หลายตัวในฉากเดียวกันต้องไม่ขยับเหมือนกันเป๊ะ
- ใน `getRig`/`newLayer` เพิ่มค่า "บุคลิก" ต่อ rig สุ่มครั้งเดียวตอนสร้าง เช่น `stride` (ขนาดก้าว/แกว่งแขน 0.85–1.15), `cadence` (ความถี่ก้าว 0.9–1.1), `lookiness` (ความถี่หันหัวตอน idle 0.6–1.4)
- ให้ `poseWalk` / `poseIdle` ใช้ค่าเหล่านี้คูณแอมพลิจูด/ความถี่ (อย่าเปลี่ยนค่าเฉลี่ย ท่าเดินโดยรวมต้องดูเหมือนเดิม)
- ลูกค้า (`ShopperService`) ให้ความเร็วเดินต่างกันเล็กน้อยต่อคน (เช่น ±15%) พนักงานคงที่ได้
- ทำเป็นข้อมูลต่อ rig ไม่ใช่ global ต้องไม่กระทบ NPC ตัวอื่น

## ข้อ 2 — หันหัวหาเป้าหมาย
เป้าหมาย: NPC "รู้" ว่ามีอะไรอยู่รอบตัว
- เพิ่ม `NpcBuilder.lookAt(model, worldPos: Vector3?)` ตั้งเป้าหมายให้หัว/คอหันไปหา (nil = เลิกมอง) หัน `Neck` (และ `Waist` เล็กน้อย) ด้วยการเบลนด์นุ่ม ๆ จำกัดมุมไม่เกิน ~±1.0 rad ถ้าเป้าหมายอยู่หลังตัวให้ไม่หัน
- ทับค่า `Neck` ของ layer ในลักษณะเดียวกับที่ `CARRY_POSE` ทับแขน แต่ต้อง lerp เข้า-ออก ไม่กระตุก
- การใช้งานใน `EmployeeService`:
  - ช่าง/ช่างพ่นสี: ตอน `setWorking(true)` ให้มองไปที่รถในอู่ของตัวเอง
  - แคชเชียร์ / พนักงานต้อนรับ: ถ้ามีผู้เล่น (`Players`) เดินเข้ามาในระยะ ~18 studs ให้หันหัวตาม ถ้าเข้าใกล้ ~10 studs และพ้น cooldown (เช่น 25 วินาที) ให้ `idle.wave(1.5)` หนึ่งครั้ง
  - เช็กระยะแบบถี่ต่ำ (เช่น ทุก 0.5 วินาที) รวมในลูปเดียวต่อ plot ไม่ใช่ลูปต่อ NPC
- ลูกค้าที่หยุดหน้าชั้นให้มองไปที่สินค้า (ชั้น)

## ข้อ 3 — การเลี้ยวและหยุดนุ่มขึ้น
เป้าหมาย: ไม่ให้เดินเป็นเส้นตรงหักมุมแบบเครื่องจักร
- ใน `walkPath` ทำให้มุมระหว่างจุดเป็นโค้ง (เช่น ตัดมุมด้วยรัศมีเล็ก ๆ ~1.5–2.5 studs หรือใช้จุด waypoint ที่ผ่อนเข้าไปก่อนถึงจุดจริง) โดยจุดสุดท้ายยังต้องไปถึงตำแหน่งเป๊ะ
- ลดความเร็วเล็กน้อยก่อนเลี้ยวมุมแหลม และเอียงลำตัว (`Root` roll ~0.05–0.1 rad) ตามทิศเลี้ยวแบบซ้อนเข้ากับ `poseWalk`
- ถ้ามีรอบหยุดที่ปลายทาง ให้หมุนหาทิศสุดท้ายหลังหยุดเดิน (มี `turnTo` อยู่แล้ว) อย่าให้ "หมุนทันที"
- (ไม่บังคับ) ลูกค้าสองคนที่กำลังเดินสวนกัน ให้เบี่ยงข้างเล็กน้อย — ถ้ายุ่งเกินไปให้ข้ามและจดไว้ใน TODO

## ข้อ 4 — ท่าทำงานมีผลที่มองเห็น
เป้าหมาย: การซ่อมต้องดู "ทำจริง" ไม่ใช่แค่ขยับแขน
- เพิ่ม callback/event จาก layer `work` เมื่อถึงจังหวะสำคัญ: ท่า hammer = ตอนเริ่ม "strike" (ช่วง `p` ผ่าน 0.65 ใน `poseWork`) ให้ตรวจการข้ามขอบแบบไม่สร้าง garbage ต่อเฟรม
- เมื่อ strike: ปล่อยประกายสั้น ๆ ด้วย `ParticleEmitter:Emit` (สีส้ม-เหลือง, อายุ ~0.25 วินาที, จำนวนน้อย) ที่ปลายเครื่องมือ (ดู `setTool` ว่าชิ้นส่วนเครื่องมืออยู่ที่ไหน) สร้าง emitter ครั้งเดียวต่อ NPC แล้วใช้ซ้ำ
- ท่า spray (ช่างพ่นสี): ละอองสีบาง ๆ ที่ปลายหัวพ่น ใช้สีเดียวกับชุดหรือสีรถที่กำลังพ่น เปิด-ปิดตาม `work.play/stop`
- ท่า reach (จัดของ): ไม่ต้องมีเอฟเฟกต์ แต่ตอนวางของให้มีจังหวะก้มลงเล็กน้อยก่อนปล่อยกล่อง (ใน `stockLoop` ของ `EmployeeService`)
- จำกัดจำนวน particle ให้ต่ำ (ดูผลต่อ 4 plot × หลายคนพร้อมกัน) ห้ามเปิด emitter ค้างเมื่อ NPC ไม่ได้ทำงาน
- ไม่ใส่เสียง (ข้อ 1 ของกติกา)

## ข้อ 5 — ลูกค้าหลากหลายขึ้น
เป้าหมาย: ลูกค้าแต่ละคนดูเป็นคนละคน
- `NpcBuilder.randomShopper` ตอนนี้สุ่ม: เสื้อ, กางเกง, ผิว, ผม (4 ทรง), หมวกแก๊ป 28%, ถุงผ้า/เป้ ขยายเพิ่มด้วยชิ้นส่วนที่ weld เอง เช่น
  - แว่นตา, ผ้าพันคอ/ผ้าโพกหัว, หมวกไหมพรม, ฮู้ด, กางเกงขาสั้น/แขนยาว, ลายเสื้อง่าย ๆ (แถบ/กระเป๋าเสื้อ)
  - ท่าทางเล็ก ๆ ประจำตัว: ถือโทรศัพท์ตอนรอ (แขนขึ้น + ชิ้นส่วนโทรศัพท์เล็ก ๆ), ล้วงกระเป๋า ฯลฯ (ใช้กลไกเดียวกับ `CARRY_POSE`/layer เดิม อย่าสร้างระบบใหม่)
- ทุกชิ้นส่วนใหม่ต้อง `CanCollide=false`, `CanTouch=false`, `Massless=true` (ใช้ `attach`) และ **ไม่กระทบ** `rootHeight`/`HipHeight`/การวางเท้าบนพื้น ห้ามปรับสเกลลำตัว
- สุ่มแบบถ่วงน้ำหนัก ไม่ให้ทุกชิ้นโผล่พร้อมกันในคนเดียว (ส่วนใหญ่ควรดูเรียบ ๆ แค่ 1–2 ลักษณะเด่น)
